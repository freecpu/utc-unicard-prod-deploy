## 五、★ SOP-07 §5 原命令的两处缺陷（首次按规程执行即暴露）

SOP 自身写过「首次按本规程执行时，须在证据里记录实际使用的形态」。本轮**首次**按 §5 执行，两处缺陷立即暴露：

**缺陷 ①：丢子目录层级**
`find dist-staging-<批次> -type f ! -name index.html -exec cp -a {} dist/ \;`
会把 `dist-staging/static/help.jpeg` **平铺**成 `dist/help.jpeg`（`cp` 到目录取 basename），`static/` 层级丢失。

> 为何此前从未暴露：G7 当时用的是 `cp -a dist-staging-g7/. dist/` 一次性覆盖，§5 的两步法是后来改写的、**没有实跑过**。

**缺陷 ②：把交付元数据落进生产静态根**
同一条命令会连带把 `BUILD-INFO`、`SHA256SUMS.txt` 复制进 `dist/` → **公网可读构建机名**（G2 已因同样理由把证据件移出 web 根）。

**实际采用（已写入 `anchors/agent-mp.env` 的 `DEPLOYED_SWAP_FORM`）**：

```bash
# ① 证据件先移出 staging
mv dist-staging-G6-20261124/BUILD-INFO dist-staging-G6-20261124/SHA256SUMS.txt delivery-G6-20261124/
# ② 先落非 index 资源，用 --parents 保留相对层级
cd dist-staging-G6-20261124 \
  && find . -type f ! -name index.html -exec cp -a --parents {} /data/apps/agent-mp/dist/ \;
# ③ 最后落 index（唯一生效开关）
cp -a index.html /data/apps/agent-mp/dist/index.html
```

> `--parents` 必须配合 `cd staging && find .`（路径为 `./static/...`）；若从上层目录 `find`，
> 会把 `dist-staging-G6-.../static/...` 整串带进目标，形成 `dist/dist-staging-G6-.../static/...` —— 本轮已避开。
